# Formal verification map

## Current boundary

The Kani suite has 77 passing harnesses. These establish bounded properties for selected functions and domains; they do not prove the complete program. Seven integration tests exercise the runner and public notation API end to end; their finite scenarios are not formal proofs.

Verus verifies the body and postconditions of the production `occupy_square` helper in `vendor/qchess/src/quantum.rs`. `selected_squares_fit`, the collision predicate used by `Position::states`, calls this exact helper. The contract covers dead halves, out-of-range squares, occupied-square rejection, and successful occupancy updates. Reproduce it with Verus 0.2026.11.02.8bf68ee:

```sh
env -u RUSTUP_TOOLCHAIN cargo verus verify --manifest-path vendor/qchess/Cargo.toml --features verus
```

## Next proof obligations

1. **`Position::states`:** generalize the full-vector materialization proof beyond the retained one-split fixture. The collision predicate, board builder, and production mask visitor have broad symbolic coverage, while symbolic vector materialization exceeded four minutes under CaDiCaL.
2. **`Position::analyze` and `play`:** prove production legal-branch checks and collapse selection compose with `CandidateAccumulator`, `unreachable_states`, and `apply_plan`; direct Kani proofs of `analyze`, `plan_move`, and branch reach did not finish within their five-, five-, and three-minute windows on fixed fixtures. Candidate/id allocations are removed from the valid `plan_move` path and candidate uniqueness is now proved independently, but branch checks and `Board::find_move` still need a tractable proof boundary before the complete transition can be verified.
3. **Notation:** prove formatting then parsing preserves each representable intent, and parsing never produces out-of-range squares or invalid masks.
4. **Board transitions:** generalize the fixed special-move proofs over colors, files, ranks, and promotion kinds; establish `apply`/`key_after` agreement for every legal generated move.
5. **Runner:** extend the field-level config proofs to the complete JSON validator and schedule cardinality/opening assignment; prove provider failures cannot create completed game records, and generalize persistence and audit properties while retaining E2E coverage for HTTP and filesystem behavior.
6. **Glicko-2:** verify integer/control-flow invariants and compare the floating-point implementation against published reference vectors; state explicit input ranges for any numeric proof.

## Reproducing current checks

```sh
cargo test --workspace --locked
cargo install --locked kani-verifier --version 0.68.0
cargo kani setup
cargo kani --workspace --output-format terse
env -u RUSTUP_TOOLCHAIN cargo verus verify --manifest-path vendor/qchess/Cargo.toml --features verus
```

The current Kani suite has 77 harnesses (47 qchess, twenty-seven runner, three Glicko-2). No harness substitutes production functions. The individual collapse commands in the README specify `--default-unwind 5`. The Glicko empty-period harness checks only rating and volatility for three fixed values, not the deviation result.
